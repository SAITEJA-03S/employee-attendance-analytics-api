# REVIEW.md

Defects identified and corrected in the starter application (`app/main.py`):

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33-37) | Naive `replace(hour, minute)` used UTC instead of IST; instant was not pre-truncated to whole seconds (R1); used `int(sec/60) > 10` which misclassified 10m 01s (e.g. 09:40:01) as 0 late minutes because `int(601/60) = 10` and `10 > 10` evaluates to False. | Calling `compute_late_minutes` at 09:40:01 IST for a 09:30 shift returned 0 instead of 10 late minutes (R2). | Converted `punch_in` to IST, computed exact elapsed seconds from shift start, evaluated `elapsed_sec > 600` (strictly more than 10 mins), and returned `math.floor(elapsed_sec / 60)`. |
| 2 | `compute_work_hours` (lines 40-41) | Used Python's built-in `round(..., 2)` which performs banker's rounding (round half to even) instead of half-up rounding (R4). | A work duration of 9.125 hours rounded to 9.12 instead of 9.13. | Created `round_half_up()` helper using Python's `decimal.Decimal` with `ROUND_HALF_UP`. |
| 3 | `compute_overtime` (lines 44-48) | Returned `max(0, int(elapsed/60))` counting overtime under 30 minutes (R3); failed on overnight shifts (`shift_end <= shift_start`) by creating `shift_end` on the same date instead of next calendar day. | Punch-out at 18:45 for 18:30 shift returned 15 overtime minutes instead of 0; overnight shift 22:00-06:00 punch-out at 06:40 returned negative/incorrect overtime. | Added `get_shift_instants()` to handle overnight date transitions, and enforced `elapsed_sec >= 1800` threshold before returning `math.floor(elapsed_sec / 60)`. |
| 4 | `create_employee` (lines 78-86) | Used check-then-insert (`find_one` then `insert_one`), causing race conditions under concurrent requests; returned BSON `datetime` object for `created_at`; missing validation for equal `shift_start` and `shift_end`. | Concurrent POST requests with the same `emp_code` crashed with unhandled `DuplicateKeyError` or inserted duplicates; response `created_at` failed OpenAPI integer schema validation. | Enforced database unique index on `emp_code` and caught `DuplicateKeyError` to return HTTP 409; converted `created_at` to epoch milliseconds int; added Pydantic validation preventing `shift_start == shift_end`. |
| 5 | `list_employees` (lines 89-96) | 1-based pagination formula bug `skip = page * page_size` skipped page 1 (items 0-19) entirely; `total` count used `count_documents({})` ignoring department filter `q`; missing `emp_code` ascending sorting. | `GET /employees?page=1&page_size=20` returned items 20-39; filtering by department returned total count of all employees. | Corrected skip formula to `(page - 1) * page_size`, updated `total` to `count_documents(q)`, and added `.sort("emp_code", 1)`. |
| 6 | `punch_in` (lines 100-121) | Check-then-insert race condition under concurrent requests; missing 404 check if employee does not exist; assigned date via `ts.date().isoformat()` ignoring overnight shift R1 rule; did not truncate `punched_at` to whole seconds; added extra `"id"` field to output. | Punch-in for unknown `emp_code` crashed with 500 `TypeError`; overnight shift punch-in at 02:00 AM was assigned to wrong calendar date; concurrent punch-ins failed to return 409. | Added employee lookup check (404); computed attendance date per R1 using `get_attendance_date()`; truncated `punched_at` to whole seconds; relied on unique compound index `(emp_code, date)` catching `DuplicateKeyError` for 409; formatted output per `AttendanceRecord` spec. |
| 7 | `list_attendance` (lines 125-150) | Loaded all matching records (`list(db.attendance_logs.find(q))`) into Python memory and sorted in Python; missing `emp_code` secondary ascending sort; missing date range validation (`date_from > date_to`). | High memory usage and slow responses on large datasets (100k records); `date_from > date_to` returned 200 empty list instead of 422. | Performed sorting, skip, and limit directly inside MongoDB using `.sort([("date", -1), ("emp_code", 1)]).skip(...).limit(...)`; added validation raising 422 when `date_from > date_to`. |
| 8 | Timestamp input validation (lines 64, etc.) | Allowed invalid types or out-of-bounds numbers for `punched_at` without epoch millisecond range constraints. | Passing `punched_at: 17833125` (seconds instead of epoch ms) was accepted instead of returning 422. | Added Pydantic `Field(ge=100000000000, le=4102444800000)` constraints on epoch ms fields. |
| 9 | Database index initialization (startup) | Starter did not create any database indexes at application startup. | Slow queries, collection scans (`COLLSCAN` in explain), and race conditions on duplicate inserts. | Added `startup` event handler creating unique and compound indexes on `employees` and `attendance_logs`. |
| 10 | History audit trail formatting (lines 116, etc.) | History items were not formatted according to OpenAPI spec and nested BSON dates inside `history.changes` were not converted to epoch ms. | Regularized records with history exposed raw BSON datetime objects or mismatched types in response JSON. | Added `format_attendance_doc()` to convert nested BSON datetimes in `history.changes` to epoch ms integers. |

### Examined and non-defect notes:
- **`GET /health`**: The overall structure of the health endpoint was fine, but was updated to ping the database via `client.admin.command("ping")` to return 503 when MongoDB is unreachable per OpenAPI spec.
